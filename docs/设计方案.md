# 《Q版泡泡堂》设计方案

> 当前版本已加入六位精灵技能、三套随机场景，以及谷谷歌歌、克劳德德、偶喷诶艾和 10 血鲁鲁旦；开始界面使用《奥奇传说》壁纸。旧小怪设计已撤销，现行规则见 [敌人与 BOSS](敌人与BOSS.md) 与 [技能与场景](技能与场景.md)；下文保留早期设计过程，历史数值以当前配置及使用说明为准。
> 项目代号：**BombIt** ｜ 版本：v1.0（设计稿） ｜ 日期：2026-10-16

---

## 1. 项目概述

### 1.1 一句话描述

一款**超可爱 Q 版风格的泡泡堂（炸弹人）同屏游戏**：放炸弹、炸砖块、吃道具、炸对手，支持单人闯关与双人同屏对战。

### 1.2 设计目标

| 目标 | 说明 |
|---|---|
| **零门槛** | 双击 `index.html` 立刻开玩，不装任何东西、不要联网 |
| **上手 10 秒** | 三个键就能玩，不做教程关也能懂 |
| **手感优先** | 移动跟手、转角不卡墙、爆炸反馈爽快 |
| **Q 版可爱** | 糖果配色 + 场景道具全圆润化；角色素材可随时替换，且**静态图也能"活起来"**（§5.4） |
| **双人同屏** | 一个键盘两个人玩，互不抢键、互不干扰 |

### 1.3 非目标（明确不做，控制范围）

- ❌ 不联网对战、不做账号系统
- ❌ 不做关卡编辑器
- ❌ 不做移动端触屏适配（桌面键盘优先）
- ❌ 不做存档/云同步

## 2. 软件选型（已确定）

### 2.1 最终结论

> **HTML5 Canvas 2D + 原生 JavaScript（ES2020）+ Web Audio API，零第三方依赖、零构建步骤。**

### 2.2 选型对比与依据（存档）

本机实测环境：Windows / Node.js v24.15.0 / Python 3.14.4 / 网络通畅（清华镜像）。

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. HTML5 Canvas + 原生 JS** | 零安装，双击即玩；浏览器原生键盘事件天生支持多键同按；Q 版美术可用代码绘制，无素材依赖；改完刷新即见效，迭代最快；发给朋友只需发文件夹 | 是浏览器页面而非独立窗口；`file://` 下不能用 ES module；性能上限不如原生（本游戏远用不到） | ✅ **采用** |
| **B. Python + pygame-ce** | 真·独立窗口；游戏循环模型经典；后续可 PyInstaller 打包 exe | **必须多一步安装**；官方 `pygame` 在 Python 3.14 上**装不上**（实测 `No matching distribution found`，见 [pygame#4627](https://github.com/pygame/pygame/issues/4627)），只能用社区分叉版 [pygame-ce](https://newreleases.io/project/pypi/pygame-ce/release/2.5.6)；改代码要重启进程；中文 HUD 需手动指定字体 | ⛔ 未采用（有环境风险，多一道安装工序） |
| **C. Node.js + Electron** | 可做独立 exe 窗口；用 Web 技术写界面 | 为小游戏引入 200~300MB 依赖、打包后 exe 150~250MB；多出打包流水线；开发需"改码→构建→重启"；体验收益仅等于把标签页换成窗口 | ⛔ 未采用（成本收益不成比例） |

### 2.3 关键决策说明

**为什么不用 ES module？**
浏览器在 `file://` 协议下会因 CORS 策略拒绝加载 `<script type="module">`。为了保证"双击就能玩"，全部代码采用**传统 `<script>` 标签 + IIFE + `window.BI` 命名空间**的组织方式。这样既能双击运行，也能放在 http 服务器下运行。

**为什么这不会影响以后做 exe？**
若日后需要独立窗口程序，可在方案 A 的代码上直接套一层 Electron/Tauri，**游戏逻辑一行都不用改写**。反之先上 Electron 则没有退路。

## 4. 玩法设计

### 4.1 游戏模式（三种）

开始界面横向排列三个卡片，方向键/鼠标选择，背景使用《奥奇传说》壁纸。

| 模式 | 目标 | 核心体验 |
|---|---|---|
| **单人 · 闯关打怪** | 炸死地图上全部敌人 → 过关 → 进入下一关 | 关卡递进、敌人 AI、越玩越紧张 |
| **单人 · 计时拆砖** | 在 180 秒内炸光所有软砖块 | 纯技巧、拼效率、刷分 |
| **双人 · 对战** | 炸死对手，先得 2 分者胜 | 同屏对抗、互相阴人 |

### 4.2 操作方式（严格遵守需求）

| 模式 | 玩家 | 移动 | 放炸弹 |
|---|---|---|---|
| **单人** | 1P | `↑` `↓` `←` `→` 或 `W` `A` `S` `D` | `空格` |
| **双人** | **1P** | `↑` `↓` `←` `→` | **`Enter`** |
| **双人** | **2P** | `W` `A` `S` `D` | **`空格`** |

> ⚠️ **关键实现点**：同一个 1P 在单人模式用 `空格` 放弹、在双人模式改用 `Enter`。因此键位**必须按模式查表绑定**，绝不能写死。游戏内 HUD 与开始界面都要显示当前模式的键位提示，避免玩家按错。
>
> ⚠️ **单人两套移动键**：单人只有 1P，`WASD` 没有归属歧义，所以方向键和 `WASD` 同时可用（映射表里一个动作写数组即可，`held/hit` 是「任一键成立即算」）；双人模式的 `WASD` 是 2P 的，不能给 1P 也绑上，否则一个人按键两个角色一起动。放弹/技能键在单人依旧是单键（`空格`/`Q`），`WASD` 只负责移动。

**通用按键**

| 按键 | 功能 |
|---|---|
| `Esc` / `P` | 暂停（弹出暂停菜单）／在菜单里再按一次直接继续 |
| `R` | 重开当前局 |
| `Enter` / 鼠标点击 | 菜单确认 |

**必须处理的按键边界问题**

1. 对 `↑↓←→` 和 `空格` 调用 `preventDefault()`，否则页面会滚动、按钮会被误触发。
2. 窗口失焦（`blur`）时**清空所有按键状态**并自动暂停，否则切回来角色会一直朝一个方向跑。
3. **键盘无冲（n-key rollover）提示**：廉价键盘同时按 3 个以上键会丢键，尤其方向键。单人模式因此同时支持 `WASD` 移动，另外还在设置里提供 **"1P 备用键位"**（`IJKL` + `U`）作为兜底方案，并在帮助页说明此现象。

### 4.3 地图设计

**网格规格**

- 逻辑网格：**15 列 × 13 行**
- 单格边长：**48 px** → 战场 720 × 624
- 顶部 HUD 条：72 px
- 画布逻辑分辨率：**720 × 696**，再按窗口尺寸等比缩放（保持宽高比），并用 `devicePixelRatio` 保证高清屏不糊

**瓦片类型**

| 值 | 类型 | 说明 |
|---|---|---|
| `0` | 空地 | 可通行、可放炸弹 |
| `1` | 硬墙 | 不可破坏、阻挡移动与火焰 |
| `2` | 软砖 | 可被火焰炸掉，可能藏道具 |

**生成规则**

1. 最外圈一圈全部为**硬墙**（`x=0`、`x=14`、`y=0`、`y=12`）。
2. 内部硬墙**随机摆放**（约 22% 的内部格子，平均 31 块），形成每局都不一样的骨架。
3. 其余空格按概率填**软砖**：对战模式 42%、闯关模式 38%、拆砖模式 55%。
4. **出生点保护**：出生点自身及紧邻格不放硬墙；菱形范围内清掉软砖，避免开局被堵死。
5. **结构校验**（见下）。

**随机硬墙：构造即合法**

原来用的是经典棋盘格 `(x%2==0 && y%2==0)` 柱子 —— 规矩、但**每局一模一样，太单调**。
改成随机之后，必须自己保证地图还是能玩的，做法是**每放一块就立刻验证，破坏结构当场撤销**：

- 把所有候选格打乱，依次尝试放置
- 每放一块就跑一次结构校验，不合格就立刻撤掉这一块
- 结果是「**构造即合法**」，不需要事后反复重生成碰运气

结构校验两条要求（软砖一律算可通行，因为它能被炸开）：

| 要求 | 含义 |
|---|---|
| **全图连通**（硬要求） | 所有非硬墙格子互相连通，**不许出现走不到的格点**——那种四面封死的孤岛 |
| 每个格子至少 `MIN_EXITS` 个出口 | 默认 `MIN_EXITS = 1`，即**允许只有一条进出的走廊（死路）**。连通性本身已经蕴含"至少 1 个出口"，所以此时真正把关的是连通性。想连死路也禁掉就调成 `2` |

> 实测（200 个种子）：**不连通 0 张、出口数为 0 的格子 0 个、最小出口数 1、200 种不同布局**，
> 其中 **199 张图含"只有一条进出的走廊"** —— 这正是 `MIN_EXITS = 1` 放开的效果。
> 约束真正开始起作用是在约 57 块硬墙（40% 密度）之后，我们只用 31 块，所以地图依然开阔。
> 想回到经典棋盘格就把 `config.js` 的 `RANDOM_WALLS` 改成 `false`。

**连通性校验**

把「软砖」视为可通行（因为它能被炸开）后做 BFS，要求：

- 所有出生点互相连通；
- **每一块软砖都挨着一个可达格**——否则那块砖永远炸不到，拆砖模式就成了死局。

> ⚠️ **踩过的坑（已实测修正）**：最初用「开局不用炸就能走到的空地比例 ≥ 60%」当合格标准，结果 **84% 的正常地图被判废并降级成空白地图**（一局 300 张图的实测数据）。原因是泡泡堂的地图本来就该到处是软砖、要一路炸过去，这个标准把正常地图全误杀了。修正后降级率降到 **0%**，平均每张图 48 块软砖。

**出生点**

- 1P：左上 `(1,1)` ｜ 2P：右下 `(13,11)`
- 闯关模式敌人：从距离 1P 至少 6 格的位置随机取点

### 4.4 炸弹与爆炸

| 参数 | 默认值 | 说明 |
|---|---|---|
| 引信时长 | 2.4 秒 | 比经典版略长，给 Q 版玩家更宽容的反应时间 |
| 引爆前闪烁 | 最后 0.6 秒 | 闪烁频率加快 + 变红，明确"要炸了" |
| 初始火力 | 1 | 火焰从炸弹格向四个方向各延伸 1 格 |
| 火力上限 | 8 | |
| 初始炸弹数 | 1 | 可同时存在的炸弹数量上限 |
| 炸弹数上限 | 8 | |
| 火焰持续时间 | 0.45 秒 | |
| 连锁延迟 | 0 帧（立即） | A 的火焰碰到 B，B 当帧引爆 |

**爆炸结算规则（按顺序）**

1. 从炸弹所在格出发，向**上/下/左/右**四个方向逐格推进。
2. 遇到**硬墙** → 该方向停止（硬墙本身不显示火焰）。
3. 遇到**软砖** → 该格显示火焰、软砖被摧毁，**该方向停止**。
4. 遇到**炸弹** → 该格显示火焰，并**当帧引爆该炸弹**（连锁反应）。
5. 火焰格内的玩家/敌人 → **死亡**。

**爆炸会烧掉地上的道具**（经典规则，`config.js` 的 `BURN_ITEMS` 可关）。
被烧掉时有音效 + 粒子反馈 —— 否则玩家会以为是显示 bug。

> ⚠️ **顺序陷阱**：必须**先烧道具、再炸砖掉道具**。反过来的话，砖块刚掉出来的道具正好落在火焰格里，会被同一发爆炸立刻烧掉 —— 结果就是道具几乎永远见不到。这条有专门的测试守着。

**爆炸范围预览与倒计时（已实现，但默认关闭）**

`config.js` 里有两个开关，默认都是 `false`：

| 开关 | 效果 |
|---|---|
| 小天「潜能洞察」 | 释放技能后的 6 秒内显示爆炸范围；其他角色没有范围预览入口 |
| `SHOW_FUSE_TIMER` | 绕炸弹一圈的倒计时环 + 弹身上的剩余秒数 |

功能保留着，改开关就能开回来。留着的原因是实现过程里有两条经验值得记下来：

> ⚠️ **预览和真实爆炸必须共用同一份计算**（`rules.bombCells`）。分成两处写迟早会对不上，而「显示的范围和实际炸的范围不一致」是最伤玩家的 bug。测试里有一条**不变量**专门比对这两者。
>
> ⚠️ **倒计时必须画在角色之上**。玩家踩在自己刚放的炸弹上是常态，跟着弹身一起画在角色下面的话，读数正好被自己的角色挡住，等于没有。

**放炸弹的限制**

- 只能放在**玩家中心所在的那一格**。
- 该格已有炸弹 → 不能放。
- 当前场上自己的炸弹数已达上限 → 不能放。
- **站在自己刚放的炸弹上可以走出去，但走出去之后炸弹变为实体、不能再走回来**（经典且关键的规则，必须实现）。

### 4.5 道具系统

软砖被炸毁时，**30% 概率**掉落道具。道具外观为上下浮动的方形徽章 + 光晕，走过去即拾取。

| 优先级 | 道具 | 效果 | 上限 |
|---|---|---|---|
| 必做 | 🔥 **火力** | 火焰延伸 +1 格 | 8 |
| 必做 | 💣 **炸弹数** | 可同时放置的炸弹 +1 | 8 |
| 必做 | 👟 **速度** | 移动速度 +10% | +50%（封顶，太快会失控） |
| 选做 | 🛡️ **护盾** | 5 秒内免疫一次火焰伤害 | — |
| 选做 | 🦶 **踢弹** | 撞到炸弹可把它踢出去（滑行到撞墙或撞物） | — |

### 4.6 敌人 AI（单人闯关模式）

| 敌人 | 外观（Q版） | 行为 | 速度 |
|---|---|---|---|
| **果冻怪** | 半透明绿色果冻，会抖，带小嘴 | 随机游走，撞到障碍就换方向，且尽量不原路返回 | 0.40 格/秒（玩家 9%） |
| **追踪怪** | 紫色幽灵，下摆是波浪，有生气的小眉毛 | 用 **BFS 距离场** 朝玩家逐格逼近 | 0.68 格/秒（玩家 15%） |
| **投弹怪** | 橙色胖墩，怀里抱着一颗小炸弹 | 靠近到 1~3 格时**自己放炸弹**，放完立刻朝反方向撤 | 0.75 格/秒（玩家 16%） |

> ⚠️ **单位踩过的坑**：这几项原本注释写的是「玩家基础速度的倍数」，但实现是
> `e.speed * CFG.TILE * dt`，也就是 **格/秒**。实际跑出来敌人只有玩家的 10% 左右
> （玩家 4.60 格/秒，果冻怪 0.50），比设计意图慢了近十倍。现在注释和实现已对齐，
> 并把「相当于玩家的百分之几」直接标在表里。
>
> 数值调整（按手感反馈）：**果冻怪 0.50 → 0.40**（最常见的杂兵，慢一点让你有走位空间）、
> **投弹怪 0.46 → 0.75**（它要停下来放炸弹，走得太慢就完全没威胁，原本是全场最弱）。
> 调整后投弹怪成了三种里最快的，果冻怪最慢。
>
> 有一条测试专门守着「**没有任何敌人比玩家跑得还快**」——包括满级加成之后，
> 这是"永远躲得掉"的前提。

**威胁图（Danger Map）—— 让敌人显得聪明的关键**

维护一张与地图同尺寸的表 `world.danger`，记录每格「还有多少秒会变危险」：

| 值 | 含义 |
|---|---|
| `0` | 安全 |
| `>0` | 这么多秒后会挨炸（数值就是炸弹引信剩余时间） |
| `-1` | 正在燃烧，立刻致命 |

每帧重算一次（15×13 格 × 最多 8 颗炸弹 ≈ 一千多次运算，开销可忽略）。计算时正确考虑**硬墙挡火**与**软砖吸火**。

敌人的决策优先级：

1. **躲危险**（最高）：脚下有威胁就往安全格跑
2. **类型化行为**：追人 / 放炸弹
3. **随机游走**：尽量不原路返回，避免来回抽搐

> **四面楚歌怎么办**：如果连一颗自己刚放的炸弹把四周全覆盖了、一个安全格都没有，敌人不会摆烂乱撞，而是**优先排除正在燃烧的格子，再挑「剩余时间最多」的那格**，尽量拖到最后一刻。

于是玩家一放炸弹，旁边的敌人就开始逃 —— "敌人怕我的炸弹"这件事立刻就能被感知到，成就感很强。

> 威胁图仅供 AI 内部规划。D 键通用显示和全局范围开关已删除，爆炸范围只在小天「潜能洞察」生效时显示。

**关卡递进**

- 第 N 关敌人数 = `min(2 + N, 8)`，速度系数 `1 + 0.04 × (N-1)`（上限 1.45 倍）
- 敌人种类随关卡解锁：第 1 关只有果冻怪，第 2 关加入追踪怪，第 3 关加入投弹怪
- 敌人出生点**至少离玩家 6 格**，不会开局就被贴脸
- **过关保留玩家的火力 / 炸弹数 / 速度成长**，并补 1 条命（上限 5），形成正反馈
- 打死敌人有 45% 概率掉道具
- 每 5 关一个 Boss（3 条血、多阶段）—— 列为选做，见 §4.9.1

### 4.7 双人对战规则

- 出生在**对角**（1P 左上 / 2P 右下），保证公平。
- 单局定胜负，**先得 2 分者获胜**（三局两胜）。
- 一方被炸死 → 对方 +1 分 → 3 秒倒计时"准备"→ 重开本局（地图**重新随机生成**，防止背板）。
- **同帧双死** → 双方各 +1 分（平局处理，避免判罚争议）。若双方由此同时达到目标分 → 判平局。

  > ⚠️ **实现要点**：死亡不能「死一个结算一个」。第一版就是这么写的，结果同帧双死时第一个人的结算把比赛判完了，第二个人的分直接丢掉（测试抓出来的）。正确做法是**把一帧内的死亡先入队，再统一批量结算**（见 `match.resolveDeaths`）。

- **超时加速**：单局 90 秒无人死亡时，地图剩余软砖全部自动消失、炸弹引信缩短到 1.0 秒，强制加速分出胜负；再过 45 秒仍无人死亡则判平局，双方各 +1 分。

### 4.8 胜负与结算

| 模式 | 胜利条件 | 失败条件 |
|---|---|---|
| 闯关 | 炸死全部敌人 | 玩家被炸死（扣 1 命，共 3 命；命耗尽则 Game Over） |
| 拆砖 | 180 秒内炸光所有软砖 | 时间耗尽仍有软砖 |
| 对战 | 先得 2 分 | 对手先得 2 分 |

**结算界面**：显示胜负横幅、本局耗时、吃到的道具统计、最高连爆数，并提供「再来一局 / 返回菜单」。

### 4.9 进阶机制（选做，待确认）

#### 4.9.1 Boss 战（现为10关冒险：第5关、第10关最终战）

当前实现的关卡与BOSS规则以[敌人与BOSS](敌人与BOSS.md)为准；以下为早期设计记录。

Boss 不是"变大的小怪"，而是有**阶段变化**的考试关。占 **2×2 格**，头顶独立血条，共 **3 条血 = 3 个阶段**：

| 阶段 | 触发 | 行为 |
|---|---|---|
| **一 · 试探** | 开局 | 缓慢朝玩家移动；每 4 秒扔出 3 颗自己的炸弹（引信 3.5 秒更长，但火力 3 格） |
| **二 · 认真** | 掉 1 条血 | 移速 +40%；改为一次扔 5 颗摆成**十字**，切碎玩家走位空间 |
| **三 · 暴走** | 掉 2 条血 | 引信缩到 1.5 秒；并**开始炸掉地图硬墙**——场地越打越开阔、掩体越来越少，逼迫正面对决 |

- **受伤**：被火焰烧到 3 次才死；每次被烧到后有 **1.5 秒无敌 + 全身变白闪烁**，防止被一次连爆秒杀。
- **奖励**：击杀后撒 5 个道具 + 过关动画。
- **价值**：普通关是"清场"，Boss 关是"考试"，把走位、连锁、道具运用全考一遍，游戏有高潮。
- **成本**：多一个 AI 状态机 + 血条 UI + 一个 Boss 绘制。

#### 4.9.2 踢弹（道具）

吃到「踢弹」后解锁：**走到炸弹旁边会把它推出去**。

- 炸弹沿推动方向滑行，一直滑到撞上**硬墙 / 软砖 / 另一颗炸弹 / 敌人**为止，停在那一格。
- **滑行中炸弹照常在倒计时**，踢出去的随时会炸。
- 滑行的炸弹**碰到人不造成伤害**，但会停下（同时挡住对方的路）。
- 需额外做滑行动画（炸弹滚动 + 速度插值）。

**战术价值**（对战模式最骚的机制）：把炸弹踢向对手隔半张图阴人；对手把炸弹贴你脸上一脚踢走自救；把炸弹踢进死角炸出一条道具走廊。**这是高手与新手的分水岭，装上它对战博弈深度直接翻倍。**

#### 4.9.3 护盾（道具）

吃到后套一个半透明气泡，持续 **5 秒**：

- 效果：**免疫一次**火焰伤害。
- 被炸到时气泡"啪"地碎掉（碎裂粒子 + 音效），角色进入 1 秒无敌闪烁，但**不死**。
- 5 秒内没被炸到 → 气泡自行消散。

**战术价值**：护盾给的是**"敢冲"的勇气**——敢冲进爆炸区抢道具、敢强行突破封锁、敢贴脸换命。它把节奏从"一味躲"变成"可以赌一把"。实现很轻：一个状态位 + 一次性消耗 + 一个气泡绘制。

#### 4.9.4 最高分记录

用浏览器 `localStorage`，在开始界面展示：拆砖模式最快通关时间、闯关模式到达的最高关卡、对战模式双方累计胜场。约 20 行代码。

## 5. 美术与音效

### 5.1 美术分工（关键决策）

| 类别 | 来源 | 原因 |
|---|---|---|
| **角色**（1P / 2P / 敌人） | **外部素材，由用户导入** | 你想用自己喜欢的角色图 |
| **场景与道具**（地板 / 硬墙 / 软砖 / 炸弹 / 火焰 / 道具 / 粒子） | **Canvas 2D 程序化绘制** | 这些形状简单、数量多、且需随状态变色（炸弹闪烁、火焰渐变），程序化比贴图更灵活且体积为零 |

### 5.2 场景与道具美术（程序化）

- **配色**：马卡龙/糖果色系，高饱和但柔和。
  - 地板：薄荷绿 `#A8E6A1` / 浅草绿 `#98D891` 棋盘格交替
  - 硬墙：奶油灰 `#B8B8C8` 带圆角与高光
  - 软砖：砖红 `#E88B6A` 带裂纹
  - 1P 标识色：天蓝 `#5EC8F0` ｜ 2P 标识色：蜜桃粉 `#FF9EB5`
- **炸弹**：黑色圆球 + 高光 + 脉动缩放；引信将尽时整体变红、闪烁加快
- **火焰**：中心白 → 橙 → 红的**圆角十字**，3 帧扩张 + 消退
- **道具**：圆角方形徽章 + 图标 + 上下浮动 + 光晕
- **Q 版圆润化**：所有形状一律圆角、加柔和描边，不用硬直角

### 5.3 角色素材系统

角色来自 `assets/characters/` 下的图片，由 **`assets/characters.js`** 配置。

> ⚠️ **为什么是 `.js` 而不是 `.json`**：浏览器在 `file://` 下会以 CORS 为由拒绝 `fetch()` 本地 json 文件，而 `<script>` 标签不受此限制。为了保住「双击 index.html 就能玩」，配置必须用 script 标签加载，所以做成 `.js`。

**未加载到素材时**（文件缺失 / 路径写错 / 还在加载），游戏自动回退到极简几何占位小人（圆形脑袋 + 方形身体 + 1P/2P 标识色 + 落地阴影），**绝不白屏**，并在 HUD 上显示素材状态。

**素材配置格式**（`assets/characters.js`）

```js
BI.CHARACTERS = {
  version: 1,
  characters: {
    xiaonuo: {
      name: '小诺',                              // HUD 上显示的名字
      image: 'assets/characters/xiaonuo.png',    // 相对 index.html
      height: 1.55,                              // 显示高度 = height × 格子边长(48px)
      anchor: [0.5, 0.88],                       // 锚点：水平居中，垂直 88% 处对准脚底
      flipForLeft: true,                         // 向左走时水平翻转
      tint: null,                                // 可选整体染色，用于区分 1P/2P
      motion: { bounce: 4, wobble: 4, breathe: 0.04, squash: 0.22 }
    }
    // ...
  },
  defaults:   { p1: 'xiaonuo', p2: 'axiu' },     // 各位置默认角色
  selectable: ['xiaonuo', 'axiu', 'arui', 'xiaoyan', 'xiaotian']
};
```

> **锚点是关键**：`anchor` 那个点必须真的落在角色脚上，否则角色会「飘」起来。图片是自动裁剪到不透明边界的，所以如果角色有尾巴/飘带垂到脚以下，`anchor[1]` 要相应调小（例如 0.88）。

### 5.4 静态图动效补偿（本方案的核心设计）

**问题**：网上的角色图绝大多数是**单张静态立绘**，不是游戏精灵图。直接拿来做角色，走起来就是"一张贴纸在平移"，Q 版最值钱的可爱感会全部丢失。

**对策**：用程序在静态图上叠一层"活的"动效：

| 机制 | 效果 | 触发时机 |
|---|---|---|
| **弹跳** | 整体上下正弦位移 | 移动时 |
| **摇摆** | 绕脚底锚点轻微旋转（±4°） | 移动时，与弹跳**错开相位**，形成"一颠一颠"的走路感 |
| **挤压拉伸** | 下压 → 弹出（squash & stretch） | 放炸弹、受击 |
| **呼吸** | 极轻微整体缩放（±4%） | 待机时 |
| **朝向翻转** | 水平镜像 | 向左移动时 |
| **椭圆落地阴影** | 脚下阴影，离地时缩小变淡 | 全程 ← **对"活着"的感觉贡献最大的一项** |
| **受击白闪** | 整体叠白 | 被炸到 |
| **死亡** | 变白 → 旋转飞起 → 淡出 + 星星粒子 | 死亡 |

> **关键点**：所有动效都绕**脚底锚点**进行（`anchor: [0.5, 0.85]`），角色才是"踩在地上弹"，而不是"在屏幕中间飘"。

> **取舍说明**：原本设计的"表情系统"（眨眼/冒汗/星星眼）只能用在几何占位小人上；导入的静态图无法做表情，改由上述动效补偿。这是选择"自己放图"必然的代价，属已知取舍。

### 5.5 素材处理工具

角色图片需要先把背景抠掉。本项目提供两种方式：

#### 方式一：`tools/extract_characters.py`（已实现，推荐先试）

Python 脚本，专门针对**图鉴卡片**这类「角色 + 卡框 + 名字 + 角标 + 法阵 + 水印」的图。
把图片放进 `aqcs/`，然后：

```bash
python tools/extract_characters.py --preview   # 抠图 + 棋盘底对比图 + 自检
python tools/extract_characters.py --debug     # 额外输出「被删掉的像素」染色图
python tools/extract_characters.py --dilate 3  # 调参数（屏障加粗圈数）
```

**这张卡的配色（实测，是理解一切的前提）**

| 部位 | RGB | 饱和度 |
|---|---|---|
| 卡面本体 | (252,232,143) | **0.43 —— 卡面本身就是饱和金色** |
| 法阵亮部 | (255,244,164) | 0.36 |
| 法阵暗环 | (203,116,0) | 1.00 |
| 白卡框 | (253,250,243) | 0.04 |
| 角色白毛 / 金冠 | ≈(255,255,255) / 金 | 0.0x / 高 |

**算法演进（五次尝试，前四次全错）**

| 尝试 | 结果 |
|---|---|
| ① 四角泛洪 + 固定容差 | ❌ 抠不动。卡面是渐变，泛洪跨不过去，整张卡都留下 |
| ② 「亮像素」泛洪 | ❌ 把白色系角色整个吃掉（白毛和奶油卡面亮度几乎一样） |
| ③ 「偏黄 = 背景」+ 分区 | ❌ **最坑的一次，因为它大部分时候看起来是对的。** 角色的金冠、金饰本身也是黄的，被当背景删掉 —— 结果就是「头没了一半」。阿修之所以没事，只是因为它恰好是深蓝配色、没有金白部件 |
| ④ 「饱和 = 角色」 | ❌ 卡面本身就是饱和金色（sat 0.43），整张卡都算角色 |
| ⑤ 「逐像素比色差 + 边缘封锁」 | ❌ JPEG 把描边糊开 2~3 像素，色差被"温水煮青蛙"，泛洪一路渗进角色内部，**5 个角色全被啃光** |
| ⑥ **亮=背景，暗=轮廓，靠连通性** | ✅ 最终方案 |

**最终方案**

判据只有两条：**亮度 > 195 算背景，亮度 < 190 算角色轮廓**。剩下全靠连通性。

关键认识：角色内部那些「和背景同色」的部分（白毛、金冠）之所以不会被误删，
**不是因为颜色判得准，而是因为它们在角色的深色描边里面** —— 泛洪进不去。
判据从「这是什么颜色」换成了「连不连得通」。

两个必须的细节：

1. **轮廓屏障要加粗 2 圈**。只加粗 1 圈时，小诺的描边仍有一处 JPEG 缺口，泛洪钻进去把整个身子掏空，只剩一圈轮廓线（看起来"有图"，其实废了）。
2. **回收碎片的距离不能超过 5px**。精灵名字就在角色上方约 13px 处，设成 14 会把「小诺」两个字一起抠进来。

**自检（重要）**

脚本会检查每个结果的**整块填充率 / 中段行列覆盖率**，不合格就红字报出来并返回非 0：

```
xiaonuo ->  87x153  占比 4.3%  填充 0.52  行均 0.65  列均 0.73
xiaonuo ->  85x151  占比 1.8%  填充 0.25  行均 0.29  列均 0.32  ⚠ 像是被掏空了 / 身体像是被切掉了
```

阈值是拿同一张卡片的「正常结果」和「掏空结果」实测对出来的（0.563 vs 0.246 等），
取在中间留足余量。**为什么必须有自检**：前面那些错误结果看起来都是"有图的"，
不逐个盯着看根本发现不了 —— 实际上就是这么漏到你眼前的。

#### 方式二：`tools/导入素材.html`（浏览器可视化工具，规划中）

面向「随手丢一张图进去就能用」的场景，零安装、拖拽即用：

| 功能 | 说明 |
|---|---|
| 一键去背景 | 采样四角颜色，按容差变透明；带边缘羽化防锯齿 |
| 自动裁剪 | 去掉四周透明留白 |
| 缩放与锚点 | 拖滑块调大小；**直接在地图上拖锚点对准脚底**，所见即所得 |
| 水平翻转 / 染色 | 一张图当左右两向用；染色区分 1P/2P |
| 动效调参 | 弹跳、摇摆、呼吸、挤压强度实时预览 |
| 保存 | 优先用 File System Access API 直接写入 `assets/`；不支持时退化为下载文件 + 手动拖拽 |

> **技术说明**：浏览器出于安全限制不能随意读写本地磁盘，所以导出走上面两条路径。

### 5.6 音效

**音效**全部用**振荡器 + 白噪声**实时合成，不引入任何音频文件 —— 音效一秒能响好几次，永不缺文件、不占体积。

| 事件 | 音效名 | 合成方式 |
|---|---|---|
| 放炸弹 | `place` | 短促方波"嘟"（300 → 120Hz，0.09 秒） |
| 爆炸 | `explode` | 白噪声低通扫频（900 → 70Hz，0.38 秒）+ 低频正弦轰 |
| 敌人放弹 | `enemyBomb` | 锯齿波（200 → 90Hz）—— 音调更低，一听就知道不是自己放的 |
| 吃道具 | `pickup` | 上行三音"叮咚"（C-E-G，三角波） |
| 角色死亡 | `death` | 下行滑音（600 → 90Hz，锯齿波）+ 噪声尾巴 |
| 护盾碎裂 | `shieldBreak` | 带通噪声（3200 → 700Hz）+ 下行三角波 |
| 敌人挨打 / 死亡 | `enemyHit` / `enemyDie` | 短方波下行 |
| 过关 | `levelClear` | 上行五音小旋律 |
| 胜利 / 失败 | `win` / `lose` | 上行旋律 + 收尾和弦 / 下行四音 |
| 菜单移动 / 确认 | `menuMove` / `menuConfirm` | 极短"嗒" / 两音上行 |
| 暂停 | `pause` | 下行三角波 |
| 死亡加速警告 | `sudden` | 上行锯齿波（300 → 900Hz） |

**两个必须处理的技术点**

1. **浏览器自动播放策略**：`AudioContext` 必须在**用户第一次交互之后**才能创建或 `resume()`，否则会一直处于 `suspended` 状态 —— 表现就是"全程没声音"。所以 `main.js` 在首次 `keydown` / `mousedown` / `touchstart` 时调一次 `sfx.unlock()`。
2. **限流**：同一个音效 30ms 内只响一次。连锁引爆时一帧能炸五六颗炸弹，不限流的话声音会糊成一片，还会削波。

**优雅降级**：音频环境不可用（无头浏览器、系统没声卡、创建 `AudioContext` 抛异常）时，`sfx.failed` 置位并从此不再重试，所有播放调用变成空操作 —— **音频问题绝不能影响游戏运行**。这条有无头测试专门守着。

### 6.2 主循环（固定步长 —— 必须实现）

不同刷新率的屏幕（60Hz / 144Hz）如果直接用帧间隔驱动逻辑，**144Hz 屏幕上游戏会快 2.4 倍**。因此采用**固定步长逻辑 + 插值渲染**：

```js
const STEP = 1 / 60;                 // 逻辑固定 60Hz
let acc = 0, last = performance.now();

function frame(now) {
  acc += Math.min((now - last) / 1000, 0.25);  // 上限防止卡顿后"螺旋死亡"
  last = now;
  while (acc >= STEP) { update(STEP); acc -= STEP; }
  render(acc / STEP);                // 用剩余比例插值，画面依旧丝滑
  requestAnimationFrame(frame);
}
```

### 6.3 核心数据结构

```js
map      : Uint8Array(COLS * ROWS)   // 0空地 1硬墙 2软砖
danger   : Uint8Array(COLS * ROWS)   // 该格剩余危险秒数（AI 用）

player   : { id, x, y, vx, vy,          // x/y 为像素坐标（浮点，平滑移动）
             speed, power, maxBombs, bombsOut,
             alive, shield, facing, anim }

bomb     : { cx, cy, power, fuse, ownerId, solid }   // solid: 玩家走出去后变 true

explosion: { cx, cy, cells: [[cx,cy], ...], t }      // cells 为所有火焰格
```

### 6.4 移动手感设计（决定"跟不跟手"）

- **移动单位是像素**（浮点），不是格子跳格 → 丝滑。
- **碰撞盒略小于格子**：48px 格子用 36×36 的碰撞盒，这样玩家能从窄缝里蹭过去，不会"明明看着能过却卡住"。
- **转角辅助（corner assist）**：当玩家朝某方向被墙挡住，但与相邻通道中心线偏差在 **10px 以内**时，自动向中心线微调。这是键盘玩网格游戏手感好坏的分水岭。
- 输入采用**单轴移动**：**一次只走一个轴，不许斜着走**。两个方向同时按住时，走「后按下的那个轴」（`p.axisPref`），松开其中一个立刻回到另一个轴。
  > 踩过的坑：最初实现成"两个轴都推进"（八向解耦），结果就是**斜着走** —— 既不是泡泡堂的规则，斜向撞墙的手感也很怪。改完之后，转角辅助仍然会在垂直轴上做一次最多 `ASSIST`（12px）像素的对齐吸附，那是"拐弯顺滑"的来源，不是持续斜走。

> **三条被坑出来的自动检查**（都是同类问题栽过跟头之后补的）：
> 1. **页面装配一致性** —— 三个 HTML 各自手写 `<script>` 清单，加模块时漏掉一个不会在加载时报错，而是运行到一半才炸。现在直接比对三份清单。
> 2. **中文编码自检** —— 用 PowerShell 的 `Get-Content`/`Set-Content` 往返一次带中文的 UTF-8 文件，中文会整片变乱码，而语法检查（全是 ASCII）发现不了。现在扫描所有文本文件里的典型乱码字节序列。
> 3. **对象字面量重复键自检** —— JS 里重复键**不是语法错误**，后者静默覆盖前者：`node --check` 查不出来、跑起来也不报错，只是行为悄悄不对。我在 `world` 字面量里写了两个 `burnItems`，导致「爆炸烧道具」整条功能是死的，而当时 332 项测试**全绿** —— 因为测试自己 `makeWorld`，从不走真实的 `createWorld`。现在有两道防线：源码扫描抓重复键，浏览器测试则**开真局**检查真实世界是否遵守配置。

## 9. 已知风险与对策

| 风险 | 对策 |
|---|---|
| `file://` 下 ES module 被 CORS 拦截 | 全部用传统 `<script>` + IIFE + `window.BI` 命名空间 |
| 高刷屏游戏速度变快 | 固定步长逻辑 + 插值渲染（§6.2） |
| 方向键/空格滚动页面、误触按钮 | 对游戏按键调用 `preventDefault()` |
| 切窗口后角色一直跑 | `blur` 时清空按键状态并自动暂停 |
| 键盘无冲导致丢键 | HUD 提示 + 单人同时支持 `WASD` 移动 + 设置里提供 1P 备用键位（`IJKL`） |
| 浏览器不自动播放音频 | ① 加载后仍尝试 `play()`，能吃下浏览器放行的配置；② `启动游戏.bat` 带 `--autoplay-policy=no-user-gesture-required`（独立 profile 防止参数被已有进程吞掉）；③ 被拒时置 `blocked`，在每次交互补播直到出声 |
| 随机地图把玩家堵死 | 出生点 3 格强制清空 + BFS 连通性校验 + 最多重生成 20 次 |
| 地图随机性导致不公平 | 双人模式出生点对角对称；每局重新生成防背板 |
| 浏览器不能直接读写本地磁盘 | 优先用 File System Access API 写入 `assets/`，不支持时降级为下载文件 + 手动拖拽 |
| 导入图片背景复杂（渐变/花纹）抠不干净 | 提供去背景容差滑块 + 边缘羽化；实在不行提示改用已抠好的透明 PNG |
| 静态立绘没有朝向和动作帧 | §5.4 动效补偿；左右朝向用水平翻转解决 |
| 超大图导致内存与性能问题 | 导入时限制最长边 ≤ 1024px 并等比缩小 |
| 素材文件缺失或格式损坏 | 回退到几何占位小人 + 界面提示，绝不白屏 |
