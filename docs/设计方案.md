# 《Q版泡泡堂》架构与决策档案

> 项目代号 **BombIt** ｜ 适用版本 **v2.2** ｜ 维护日期 2026-10-18
>
> 本文只保留长期有效的架构、选型与关键决策。玩法数值、关卡、敌人、技能与验收标准以现状文档和 `src/core/config.js` 为准；v1.0 设计稿中的数值表、里程碑、验收清单与早期机制已删除。

---

## 1. 项目概述

《Q版泡泡堂》是一款 Q 版泡泡堂（炸弹人）同屏游戏，使用 **HTML5 Canvas 2D + 原生 JavaScript** 编写，零第三方依赖、零构建步骤。开始界面提供单人闯关、单人计时拆砖、双人同屏对战三种模式，角色、场景与关卡内容由配置驱动。

同一套确定性内核同时驱动浏览器、CLI 与回放：浏览器负责人机对战与渲染；`cli/` 让 Agent 以 JSON 观察局面并按帧提交动作；`replay/` 按记录的动作逐帧重演并校验存档；`tests/` 直接复用内核做无头检查。因此游戏规则只实现一次，三种入口不会各自漂移。

## 2. 软件选型与依据

### 2.1 结论

**HTML5 Canvas 2D + 原生 JavaScript + Web Audio API，零第三方依赖、零构建步骤。**

- 双击 `index.html` 即可运行，不需要安装、构建或联网；键盘事件原生支持多键同按，适合双人同屏。
- 改 `src/` 后刷新页面即生效，没有编译、打包或热更新链路；场景与道具可用 Canvas 程序化绘制，不依赖贴图。
- 若日后需要独立窗口，现有逻辑可以原样套壳；本项目没有采用这条路（见 §7）。

### 2.2 选型对比（存档）

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| **A. HTML5 Canvas + 原生 JS** | 零安装、双击即玩；`file://` 可用；迭代最快；程序化美术无素材依赖 | 运行在浏览器标签页内；性能上限低于原生（本游戏用不到） | ✅ 采用 |
| **B. Python + pygame-ce** | 独立窗口；经典游戏循环；可打包 exe | 需要额外安装 Python 与包；当时官方 `pygame` 对最新 Python 没有可安装发行包，只能用社区分叉 pygame-ce；改代码要重启进程；中文 HUD 需手动指定字体 | ⛔ 未采用 |
| **C. Node.js + Electron** | 独立 exe 窗口；可用 Web 技术写界面 | 为小游戏引入庞大的依赖树与打包流水线；开发需构建后重启；收益只是把标签页换成窗口 | ⛔ 未采用 |

### 2.3 关键约束

- **不用 ES module，角色配置用 `.js`**：浏览器在 `file://` 下会以 CORS 拒绝 `<script type="module">` 与 `fetch()` 本地 JSON。全部代码采用传统 `<script>` + IIFE + `window.BI` 命名空间，`assets/characters.js` 也用脚本标签加载。
- **不做构建产物**：仓库里的文件就是运行文件；发布包只是把同一目录打包，不经过编译。

## 3. 运行方式

| 方式 | 操作 | 说明 |
|---|---|---|
| **推荐** | 双击 `启动游戏.bat` | 自动寻找 Edge/Chrome，用独立配置目录和 `--autoplay-policy=no-user-gesture-required` 启动，省去首次点击放行音频 |
| **直接** | 双击 `index.html` | 无需环境，离线可用；若浏览器拦截自动播放，点一下页面即可出声 |
| **CLI / Agent** | 双击 `启动CLI.bat`，或 `npm run play`；Agent 用 `node cli/bombit.cjs ...`，推荐 `serve --memory` | 人类终端对局等待输入时暂停；Agent 仅需 Node.js 18+，命令见 CLI 文档 |
| **回放** | 菜单右上角「对局回放」；或双击 `观看回放.bat` | 浏览器内可选择/拖入 `.replay.json`；脚本入口 `node cli/watch.cjs [--session ID] [--file 文件]`，无 Node 时回退打开 `replay.html` |
| **测试** | 双击 `运行测试.bat`；或 `npm test` | `运行测试.bat` 依次跑逻辑测试、浏览器测试、回放浏览器测试 |

浏览器要求：Chrome / Edge（启动器已适配）；其他现代浏览器需支持 Canvas 2D、Web Audio API 与 `requestAnimationFrame`。开发时改 `src/` 下任意文件后按 F5，无构建步骤。

## 4. 技术架构

### 4.1 分层与数据流

| 层 | 位置 | 职责 |
|---|---|---|
| 核心 | `src/core/` | 配置、可复现随机数、键位映射与输入状态 |
| 游戏规则 | `src/game/` | 地图生成、移动、炸弹与爆炸、道具、威胁图、敌人 AI、赛制、确定性引擎 |
| 表现 | `src/render/`、`src/audio/`、`src/scenes/` | Canvas 绘制、素材缓存、粒子、HUD、音效与配乐、菜单/暂停/结算 |
| 装配 | `src/main.js` | 启动、固定步长主循环、场景状态机、世界与音频回调装配 |
| CLI | `cli/` | 用 Node `vm` 加载同一批 `src/game/` 脚本，提供 JSON 协议、存档与动作推进 |
| 回放 | `replay/` | 复用引擎重演动作，校验每步哈希，提供播放器界面 |

数据流：输入 → `src/game/engine.js` 的 `engine.step(world, actions, 1/60)` → 事件队列 → 渲染/音效/CLI 响应。`engine.js` 不碰 DOM、渲染或音频；`src/game/snapshot.js` 负责无损 JSON 快照（保留类型数组与共享引用，`danger` 重算）；`src/game/observation.js` 输出 `bombit/1` 协议的可公开局面，不泄露 AI 计划与随机状态。

### 4.3 主循环（固定步长）

高刷新率屏幕若直接用帧间隔驱动逻辑，游戏速度会随刷新率变化。因此逻辑固定 60Hz，渲染用剩余时间比例插值：

```js
var STEP = BI.engine.STEP;               // 1/60 秒
acc += Math.min(dtReal, 0.25);           // 切标签页回来不补跑过多逻辑
for (var steps = 0; acc >= STEP && steps < 8; steps++) {
  update(STEP);
  BI.input.endFrame();                   // “刚按下”的边沿只在一个逻辑步生效
  acc -= STEP;
}
if (steps === 8) acc = 0;                // 追不上就丢弃欠账，避免死亡螺旋
render(acc / STEP);                      // 用剩余比例插值，画面依旧丝滑
```

### 4.4 核心数据结构

```js
map      : Uint8Array(COLS * ROWS)        // 0 空地 / 1 硬墙 / 2 软砖
danger   : Float32Array(COLS * ROWS)      // 0 安全；>0 还有多少秒挨炸；-1 正在燃烧
player   : { id, x, y, px, py, ... }      // x/y 为像素浮点；px/py 为上一帧位置，用于插值
bomb     : { cx, cy, power, fuse, fuseTotal, ownerId,
             passFor, freeFor, slide, byEnemy }   // 没有 solid 字段
flames   : world.flames[]                 // 每项 { cells, t, total, cx, cy, ownerId }
```

- `freeFor`：主人刚放下、还没走出去的炸弹允许踩出去；离开后置空，炸弹成为实体。
- `passFor`：当前仍与炸弹重叠、允许离开的玩家列表。
- `slide`：推弹手套把炸弹推出去后的滑行状态（方向、速度）；`null` 表示静止。
- 爆炸不是单个对象的字段，而是 `world.flames` 中的火焰记录；范围预览与真实爆炸共用 `rules.bombCells`，避免显示与判定分叉。
- `danger` 每帧由 `danger.compute` 重算；快照不持久化它，读取后按当前局面重建。

### 4.5 网格、画布与移动手感

- 逻辑网格 15 列 × 13 行，单格 48px；战场 720×624，顶部 HUD 72px，逻辑画布 720×696。
- 画布按窗口等比缩放，并用 `devicePixelRatio` 设置实际像素尺寸，高清屏不糊。
- 位移以像素浮点推进，不跳格；碰撞盒 36×36，小于 48px 格子，窄缝可蹭过。
- 一次只走一个轴；两方向同时按住时走 `axisPref`（后按下的轴）。
- 转角辅助：被挡住且与通道中线偏差不超过 `ASSIST = 12px` 时自动对齐；这是一次性吸附，不是持续斜走。
- 窗口失焦清空按键并自动暂停。

### 4.6 性能与加载

| 指标 | 现状 |
|---|---|
| 帧率 | 逻辑固定 60Hz，单帧最多补 8 步，超出丢弃欠账；渲染由 `requestAnimationFrame` 驱动并插值 |
| 代码体积 | `src/` 约 330 KB（纯文本，不含素材与 HTML）；无依赖、无构建产物 |
| 素材内存 | 角色加载时按裁切区域生成最高 512px 纹理；壁纸按屏幕尺寸只裁剪一次 |
| 加载 | 菜单优先：先加载菜单所需素材，对局素材在菜单内后台加载；失败回退占位小人/渐变背景 |

## 5. 美术与音效流水线

### 5.1 美术分工

| 类别 | 来源 | 原因 |
|---|---|---|
| 场景与道具 | Canvas 2D 程序化绘制 | 形状简单、数量多、要随状态变色；零体积、易调参 |
| 角色 | `image_gen` 按图鉴参考重制高清透明 PNG，再用 `tools/extract_characters.py` 抠图裁切 | 保留统一画风与高分辨率，运行期再缓存 |
| 敌人 / UI | `assets/enemies/`、`assets/ui/` | 与角色同一套加载与回退机制 |

- 角色素材的尺寸表、正面/背面清单与生成提示词统一见 [角色素材](角色素材.md)；运行期配置（`crop`、`height`、`anchor`、`motion`）在 `assets/characters.js`。`extract_characters.py` 是开发期工具，不是运行时依赖。
- 素材缺失、路径错误或尚未加载完成时，回退几何占位小人，绝不白屏；壁纸缺失时回退渐变背景。
- 原始高清文件保留在 `assets/characters/`；`aqcs/` 的第三方原图不进版本库。

### 5.2 静态图动效补偿

角色素材是单张立绘而非精灵图，因此用程序叠加动效，全部绕脚底锚点进行：

| 机制 | 效果 | 触发 |
|---|---|---|
| 弹跳 / 摇摆 / 呼吸 | 上下正弦位移、绕脚底轻微旋转、待机时极轻微缩放 | 移动、待机 |
| 挤压拉伸 | 下压后回弹 | 放炸弹、受击 |
| 朝向翻转 | 水平镜像；向上时切换背面素材 | 移动方向 |
| 落地阴影 | 椭圆阴影随离地缩小变淡 | 全程 |
| 受击白闪 / 死亡 | 叠白；变白 → 旋转飞起 → 淡出 + 粒子 | 受击、死亡 |

> 表情系统只适用于几何占位小人；外部静态图改由上述动效补偿，这是素材方案的已知取舍。

### 5.3 音效与配乐

- 音效：`src/audio/sfx.js` 用振荡器 + 白噪声实时合成，不引入音频文件；同一音效限流，音频环境不可用时整体降级为空操作，不影响游戏运行。
- 配乐：`src/audio/music.js` 管理五首 MP3（菜单、两首普通关、两首 BOSS 曲《鲁鲁旦别捣蛋》），用 `HTMLAudioElement` 边下边播；曲目由场景与 BOSS 存活状态推导，换曲淡入淡出。
- 自动播放：页面加载后先试播，被策略拦截则等待首次键盘/鼠标/触摸交互补播；`启动游戏.bat` 用启动参数免去这一步。

## 6. 关键决策记录

| 事项 | 决定 | 理由 |
|---|---|---|
| 技术选型 | HTML5 Canvas 2D + 原生 JavaScript，零依赖零构建 | 双击即玩、迭代最快、分发最简单 |
| 模式范围 | 单人闯关、单人拆砖、双人同屏对战三种都做 | 三种体验差异足够大，共用同一套规则与赛制 |
| 角色美术 | 由 `image_gen` 生成高清素材，再用 `tools/extract_characters.py` 抠图裁切；不做素材导入器 | 统一画风与清晰度，避免把兼容性成本推给玩家 |
| 共享内核 | 浏览器、CLI、回放、测试共用 `src/game/engine.js` | 规则只写一次，入口之间不会行为漂移 |
| 回放与存档 | 种子 + 动作历史 + 每步校验；正式回放归档到 `data/replays/` | 可复现、可验证、可逐帧观看 |
| 使用范围 | 个人学习与娱乐，非商用；已通过 GitHub Pages 与 Releases 发布 | 第三方素材权利归原权利人，不用于盈利 |
| Agent 策略 | 不附带固定策略示例 Agent，由各模型自行读状态决策 | 避免把某一种玩法固化成项目默认行为 |

## 7. 已废弃或未采纳的规划

| 规划 | 处理 | 原因 / 替代 |
|---|---|---|
| 浏览器可视化素材导入器（`tools/导入素材.html`） | 未实现 | 浏览器无法可靠写入本地磁盘，导入质量与锚点校准仍要人工；改为 `image_gen` 生成 + `extract_characters.py` 抠图 + 直接维护 `assets/characters.js` |
| `localStorage` 最高分 | 未实现 | 浏览器端不引入本地成绩存档；对局记录由回放与 CLI 归档承担，避免存档兼容与清理问题 |
| Electron 套壳 | 未实现 | 双击启动器、GitHub Pages 与 Releases 已覆盖分发；不值得为小游戏引入庞大的依赖树与打包链路 |
| 威胁图调试视图 | 未保留 | 通用调试显示会增加界面与维护成本；`danger.js` 保留 `dump()` 文本调试，游戏内范围显示只由小天「潜能洞察」触发 |
